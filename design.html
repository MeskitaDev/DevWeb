    Design Thinking no Desenvolvimento:
    Criando Soluções Centradas no Usuário

    Resolução de problemas focada nas pessoas

    No desenvolvimento de software e web, ele atua como uma ponte entre a necessidade do usuário e a construção da solução técnica.


    1. As 5 Etapas do Design Thinking Aplicadas ao Dev Web

    A. Compreender o Usuário

    O objetivo é entender quem é o usuário final, seus comportamentos, necessidades e limitações.

    O que é feito: Entrevistas, observação direta e criação de Personas (perfis fictícios baseados em dados reais).

    Visão Dev: Entender os dispositivos e contextos que os usuários utilizarão (ex.: conexões lentas, navegadores antigos ou telas pequenas).


    B. Mapear o Problema

    Organizam-se os dados da fase de empatia para identificar o problema principal a ser resolvido.

    O que é feito: Construção do Mapa de Empatia e da Jornada do Usuário, definindo declarações de problema claros (ex.: "O usuário precisa de uma forma simples de acompanhar o pedido sem criar uma conta").

    Visão Dev: Ajudar a definir o escopo funcional e os requisitos de negócio antes de desenhar o banco de dados ou a arquitetura.


    C. Ideação (Gerar Soluções)

    Momento de tempestade de ideias (brainstorming) sem julgamentos prévios.

    O que é feito: Sessões de ideação técnica e conceitual, mapeamento de fluxos de telas (User Flow) e arquitetura de informação.

    Visão Dev: Avaliar a viabilidade técnica das ideias (ex.: APIs necessárias, limites de infraestrutura, complexidade de implementação).


    D. Prototipação (Tornar as Ideias Tangíveis)

    Criação de representações visuais e interativas do produto para validar o fluxo.

    Níveis de Protótipo:

    • Baixa Fidelidade (Low-Fi): Rascunhos em papel (wireframes) para alinhar a estrutura visual rápida.
    • Média/Alta Fidelidade (Hi-Fi): Telas interativas no Figma ou Adobe XD mostrando visual, transições e regras de layout.

    Visão Dev: O protótipo serve como o "manual" de implementação. Ele orienta a estrutura HTML, os componentes CSS e a lógica de estados da interface.



    E. Validar com Usuários

    Apresentação do protótipo (ou da versão Beta) aos usuários reais para observar sua interação e colher feedbacks.

    O que é feito: Testes de usabilidade, análise de erros e métricas de conclusão de tarefas.

    Visão Dev: Identificar falhas na experiência que exigem ajustes no código ou na lógica do sistema.


    "Código é a ferramenta para construir a solução, mas o Design Thinking é o mapa que garante que estamos construindo a solução certa."
